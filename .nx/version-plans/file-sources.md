Uploads: a user with `zeteo.uploads.write` uploads a CSV or Excel file, previews and corrects it, and gets an `upload` source they own, stored in Zeteo's Postgres and queried through a read-only reader role (`UPLOADS_READER_URL`, off while unset). Owners grant, declare relations, describe, re-upload, retype, transfer and delete. Changes are audited under the sources' events with `type: "upload"` in the metadata: `zeteo.source.created`, `.updated` and the new `.deleted`, `.transferred`, `.tables_added`, `.table_reuploaded` and `.table_removed`. One sources API: `/v1/sources` serves database and upload sources alike (`POST` with `type: "upload"`, `DELETE`, `POST …/transfer`, `POST …/tables`, `PUT` and `DELETE …/tables/:tableId`, `PATCH …/columns/:columnId` for upload sources; `409 not_an_upload_source` on a database, and `409 not_a_database_source` for an upload source's archive, test, refresh, settings or schemas), its list filters by `type` and `owner_id` (`owner_id=me` for an owner holding only `zeteo.uploads.write`), and staging is `POST /v1/uploads` and `DELETE /v1/uploads/:uploadId`. The source view gains `share_count`, and an upload source's `size_bytes` is what it stores; tables gain `row_count` and `last_loaded_at`, columns `original_name`. The `UPLOAD_*` limits (bytes, rows, columns, quota, unconfirmed uploads and uploads in flight per user, xlsx workbooks read at once), start-up checks of the reader URL, the database version and Zeteo's `CREATE` privilege, "My sources" in My Zeteo, and one source page for every source (`/sources/:id`: Overview, Tables, Relations and Shared with, an Edit dialog for the settings, a back link to where it was opened from). Database sources get a size: `size_bytes` and `size_measured_at` on the source, the bytes on disk of the tables in its schemas, measured at each catalogue refresh (on Azure SQL it needs `VIEW DATABASE STATE`; a refresh that cannot read it keeps the last value), and each table an estimated `row_count` from the database's statistics (Postgres `reltuples`, or the live-row count for a table never analyzed; SQL Server `sys.partitions`), kept when a refresh cannot read them. An upload source's `last_refreshed_at` is its last load. SDK: the upload-source calls on `sources` (`create` with `type: "upload"`, `delete`, `transfer`, `addTables`, `reuploadTable`, `removeTable`, `updateColumn`), `uploads.create` and `uploads.discard`, the list's `type` and `owner_id`, and `size_bytes`, `size_measured_at` and `share_count` on `Source`. Every "who" filter in the admin UI is one searchable list of the whole directory, from the new `GET /v1/principals/all` (`zeteo.grants.read`) and `GET /v1/me/principals/all` (`zeteo.data.read`, the people and groups one may share with): `{ data, truncated }`, at most 5000 users and 5000 groups; SDK `principals.all()` and `me.allPrincipals()`.
