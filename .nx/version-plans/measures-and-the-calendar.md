Measures and the calendar: a measure is a named, described aggregate on one table of a source (`paid_revenue`), expanded by the planner into any query as `{ "measure": name }`, with the query's filters and grouping applying to it and visible only to callers granted every column it reads. `/v1/sources/{id}/measures` (list, with whether the caller may edit them and manage their editors, create, get, change, delete, `preview` of a draft with the run entry point `measure_preview`) and `/v1/sources/{id}/measure-editors`; changes need `zeteo.measures.write` (on `zeteo_admin` and `zeteo_user`) and a place on the source's editor list, and a save that would break a measure using it is refused with `measure_in_use`. One calendar per install (`GET` and `PUT /v1/calendar`, `zeteo.calendar.write` on `zeteo_admin`): working days, holidays, fiscal year start month and the time zone that relative dates follow. The query language gains `case`, date arithmetic (`dateAdd`, `dateDiff` down to whole seconds, `datePart`, date and relative literals), business-day functions over constant dates, and `fiscal_quarter` and `fiscal_year` buckets and relative units. `GET /v1/catalog`, MCP `describe_table`, `list_tables`, `list_sources`, the per-caller instructions and `query_guide` show and explain measures. A gauge chart for dashboards. New errors `measure_in_use`, `measure_needs_single_rows`, and the measure planner errors. The admin UI gains a Measures tab on a source (JSON editors with live validation, Preview, editors) and a Calendar page. Metrics and fixed measures: a measure may be `fixed` (one value that ignores the query's filters, usable from any table and as a comparison value in `where`, `having` and `case`) and may name a `date_column`; a metric is a named formula over measures of different tables of one source (`/v1/sources/{id}/metrics`: list, create, get, change, delete, `preview`, with the measures' editors and permissions; `measure_in_use` now also lists dependent metrics as `dependents`). A second query shape, `{ "metrics": [...], "bucket"?, "range"? }`, lines each measure up per period by its own date column, over HTTP, saved queries, exports, dashboards (panel time column `"range"`) and MCP, whose catalogue tools, `query_guide` and `preview_panel` cover metrics and fixed measures. `businessDaysInMonth` takes a column. MCP tools let a source's measure editors list, preview, create, change and delete its measures and metrics (`list_measures`, `preview_measure`, `create_measure`, `update_measure`, `delete_measure` and the same for metrics), by source slug and name, under the API's rules. The admin UI gains a Fixed toggle and a Date column, measure and metric forms as pages of their own, and a Metrics tab; the Calendar page puts holidays in a table with an Add holidays dialog (row by row or pasted) and saves only on changes. Not included: filters on non-date dimensions in metric queries, metrics using metrics, and elapsed or remaining business days over columns. SDK: `measures` (`list`, `create`, `get`, `update`, `delete`, `preview`, `editors`, `replaceEditors`) and `calendar` (`get`, `replace`) calls, and `metrics` (`list`, `create`, `get`, `update`, `delete`, `preview`) calls.
