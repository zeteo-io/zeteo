Measures and the calendar: a measure is a named, described aggregate on one table of a source (`paid_revenue`), expanded by the planner into any query as `{ "measure": name }`, with the query's filters and grouping applying to it and visible only to callers granted every column it reads. `/v1/sources/{id}/measures` (list, create, get, change, delete, `preview` of a draft with the run entry point `measure_preview`) and `/v1/sources/{id}/measure-editors`; changes need `zeteo.measures.write` (on `zeteo_admin` and `zeteo_user`) and a place on the source's editor list, and a save that would break a measure using it is refused with `measure_in_use`. One calendar per install (`GET` and `PUT /v1/calendar`, `zeteo.calendar.write` on `zeteo_admin`): working days, holidays, fiscal year start month and the time zone that relative dates follow. The query language gains `case`, date arithmetic (`dateAdd`, `dateDiff`, `datePart`, date and relative literals), business-day functions over constant dates, and `fiscal_quarter` and `fiscal_year` buckets and relative units. `GET /v1/catalog`, MCP `describe_table`, `list_tables`, `list_sources`, the per-caller instructions and `query_guide` show and explain measures. A gauge chart for dashboards. New errors `measure_in_use`, `measure_needs_single_rows`, and the measure planner errors. The admin UI gains a Measures tab on a source (JSON editors with live validation, Preview, editors) and a Calendar page. Not included: metrics across tables, fixed values that ignore a query's filters, and calendar functions over columns. SDK: `measures` (`list`, `create`, `get`, `update`, `delete`, `preview`, `editors`, `replaceEditors`) and `calendar` (`get`, `replace`) calls.
