# Contributing

Thanks for helping with Zeteo. Bug reports, fixes and documentation are all welcome. For a new
feature or a change to how Zeteo behaves, open an issue first so the approach can be agreed
before you write it.

## Getting set up

[README.md](README.md) covers running Zeteo locally, and [CLAUDE.md](CLAUDE.md) lists the
conventions the code follows. The suite's rules are in
[packages/zeteo/src/tests/README.md](packages/zeteo/src/tests/README.md).

## Making a change

- **Style** is checked by CI: [docs/code-style.md](docs/code-style.md). Before pushing, run

  ```sh
  npm run format && npm run sort-imports && npm run lint && npm run check
  ```

- **Tests**: add or change tests with the code. The suite runs against real Postgres and Redis
  (`npm run test:unit -w zeteo` and `npm run test:int -w zeteo`, or `docker/test/run.sh`).
- **Migrations** are generated by Prisma (`npx prisma migrate dev --create-only`), with raw SQL
  added only for what Prisma cannot express.
- **Version plans**: a change to `zeteo` needs one. Run `npm run version-plan` and commit the file
  it writes. CI's version-plan check says when one is missing
  ([Releases](docs/code-style.md#releases)).
- **Commit messages** follow [Conventional Commits](https://www.conventionalcommits.org/):
  `fix(health): …`, `feat(sources): …`, `docs: …`.

Open the pull request against `master` and fill in the template.

## What belongs elsewhere

- **Integrations with external APIs** belong in
  [dianemo-plugins](https://github.com/dianemo/dianemo-plugins).
- **Auth, file storage, webhooks, notifications and audit** belong to tereo.
